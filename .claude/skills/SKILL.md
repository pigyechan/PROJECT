# Grit_Project 초보자용 설명 모드

사용자는 삼성전자 협력사 프리랜서로 C#/.NET·Oracle DB 경력은 있지만, Java 백엔드
생태계(Gradle, Spring Boot, JUnit 5, Mockito, AssertJ, Cucumber-JVM 등)는 이번이
처음이다 (Grit_Project/CLAUDE.md 참고). "~를 설명해줘" 라는 명시적 요청이 오면 아래
방식을 항상 적용한다 — 사용자가 매번 "쉽게 설명해줘"를 덧붙이지 않아도 된다.

## 이 스킬이 적용되는 경우
- "~가 뭐야?", "~를 설명해줘", "~는 어떻게 동작해?" 처럼 **설명을 직접 요청**하는 경우.

## 이 스킬이 적용되지 않는 경우
- 사용자가 스스로 학습/고민 중인 열린 질문(설계 판단, "이거 어떻게 할까?" 류)에는
  Grit_Project/CLAUDE.md 의 기존 규칙(먼저 생각할 방향을 질문으로 유도)을 그대로 따른다.
  이 스킬은 사용자가 이미 "설명해달라"고 직접 요청했을 때만 적용되는, 그 규칙의 예외다.

## 설명 방식
- **아무것도 모른다고 가정**한다 — 해당 개념을 처음 듣는 사람 기준으로, 전문용어가
  나오면 그 자리에서 바로 풀어서 설명하고 넘어간다 (별도 용어집 없이 문장 안에서).
- **왜(Why) → 어떻게(How)** 순서 유지 (Grit_Project/CLAUDE.md 의 기존 선호와 동일).
- 가능하면 사용자가 이미 아는 C#/.NET, Oracle DB, Windows 앱 개발 경험에 빗댄 비유를
  사용한다 (예: "Gradle은 .NET의 NuGet + MSBuild를 합쳐놓은 것과 비슷합니다").
- 코드를 보여줄 때는 어떤 도구/문법이 왜 쓰였는지 옆에서 같이 짚어준다.
- 장황한 배경지식 나열보다 지금 필요한 만큼만, 그러나 건너뛰지 않고 끝까지 설명한다.
- 감성적 격려 문구는 넣지 않는다 (Grit_Project/CLAUDE.md 의 금지 규칙 유지).
