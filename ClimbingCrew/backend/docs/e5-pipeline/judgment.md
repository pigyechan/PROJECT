# AI 자기평가와 계약 테스트가 어긋난 지점

Gen 서브에이전트는 자기평가에서 "rating처럼 값이 없는 선택 필드도 응답 JSON에서 키가 생략되지 않고 null 값으로 나타난다. Jackson 기본 직렬화 설정(NON_NULL 미설정)을 근거로 하며, curl로 직접 확인했다"고 명시적으로 주장했습니다. 반면 제가 먼저 써둔 계약 테스트(`jsonPath("$.rating").exists()`)는 이 지점에서 실패했습니다 — "No value at JSON path $.rating"이라는 에러로, 마치 그 필드가 아예 없는 것처럼 보였습니다.

테스트 결과만 보고 "AI가 틀렸다"고 결론 내리는 대신, `.andDo(print())`로 실제 HTTP 응답 원문을 직접 확인했습니다. 응답 body에는 `"rating":null`이 정확히 들어 있었습니다. 문제는 AI 구현이 아니라 제가 쓴 테스트의 검증 방식이었습니다 — JsonPath 라이브러리의 `.exists()`는 "키가 null 값으로 존재함"과 "키가 아예 없음"을 구분하지 못하는 알려진 특성이 있고, 저는 그걸 모른 채 이 메서드를 썼습니다. `.value(nullValue())`로 바꾸자 테스트는 정확히 GREEN이 됐습니다.

제 판단은 이렇습니다: AI의 자기평가가 맞았고, 제가 쓴 계약 테스트가 틀렸습니다. 이 사건은 "계약 테스트는 결정적이라 믿을 수 있다"는 이번 스테이션의 전제에 예외를 하나 만듭니다 — 테스트 자체가 검증 도구의 동작을 잘못 이해하고 쓰여지면, 그 테스트는 여전히 매번 같은(잘못된) 답을 결정적으로 내놓습니다. 결정성(determinism)과 정확성(correctness)은 다른 속성이라는 것을, AI의 주장을 그냥 믿지도 않고 테스트의 RED를 그냥 믿지도 않고 원본 응답을 직접 눈으로 확인하고서야 알게 됐습니다.
