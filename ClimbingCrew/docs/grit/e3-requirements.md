# E-3: 죽은 기획서를 살아있는 요구사항으로

## 1. 죽은 기획서 3관점 비평
예시 기획서: 티켓 예매 대기열 (버튼을 누르면 대기열 등록, 순서가 되면 입장, 내 순서를 보여줌)

### 컨셉(Why) 부재 비평 — 기획자에게 던질 질문 2가지

첫째, "이 대기열이 막으려는 게 서버가 감당 못 할 동시 요청 폭주인가요, 아니면 누가 먼저 왔는지의 공정한 순서인가요?" 티켓 예약 로직을 짜면서 동시성 제어를 락 기반으로 처리한 적이 있는데, 락은 순서를 보장하지만 규모가 커지면 그 자체가 지연으로 이어진다는 것을 알게 됐습니다. 목적이 무엇이냐에 따라 대기열을 "동시 처리량을 제한하는 게이트"로 설계할지 "엄격한 순번 큐"로 설계할지가 완전히 달라집니다.

둘째, "동시에 여러 명이 결제까지 성공했을 때, 시스템이 이 충돌을 실패로 인식하고 환불을 트리거할 수 있는 구조인가요, 아니면 대기열이 애초에 한 번에 한 사람만 예약을 시도하게 만들어서 이런 충돌 자체를 차단하려는 건가요?" 실제로 짠 예약 로직에서는 동시에 들어온 두 요청이 각자 다른 객체로 티켓을 읽어오면, 둘 다 예외 없이 예약에 성공하고 나중에 저장된 쪽이 조용히 앞선 결제를 덮어쓰는 경우가 있었습니다(TicketService 코드 확인 결과 `@Lock`/`@Transactional`/`@Version` 등 동시성 제어 장치 없음). 이는 대기열의 목적이 "공정한 순서 표시"인지 "동시 접근을 원천 차단하는 안전장치"인지를 가르는 질문입니다.

### NFR 부재 비평 — 반드시 정의되어야 할 NFR 3가지

첫째, 예상 동시 접속자 수입니다. 이게 없으면 DB 커넥션 풀 크기, 서버 인스턴스 수, 락 전략을 결정할 수 없습니다.

둘째, 초당 요청 처리량(TPS)입니다. 이게 없으면 결제 게이트웨이 호출이 순간적으로 몰리는 트래픽을 감당할 수 있는지, 트래픽을 흡수할 버퍼(큐잉)가 필요한지, 오토스케일링 기준을 정할 수 없습니다.

셋째, 대기열에서 예매 페이지로 넘어가는 허용 Latency입니다. 이게 없으면 대기 상태를 DB에 저장하고 폴링할지, 인메모리(레디스) 기반으로 실시간에 가깝게 처리할지 같은 인프라 선택 자체가 불가능합니다.

### 엣지 케이스(Unhappy Path) 부재 비평

대기 중 새로고침 시 순번이 유지되는지, 아니면 새로 등록해야 하는지가 정의돼야 합니다. 중복 요청(버튼 연타 등)이 순번을 중복 생성하거나 새치기로 이어지지 않도록 멱등성 처리가 정의돼야 합니다. 이탈(대기 중 나가거나, 입장 순서가 됐는데도 응답이 없는 경우) 시 그 자리를 언제, 어떤 기준으로 다음 사람에게 넘길지(타임아웃 기준)가 정의돼야 합니다.

## 2. 본인 기능 요구사항 명세서 — 방문 기록 남기기

### 기능 요구사항
- 사용자는 암장 이름과 날짜(필수), 사진·동영상, 별점, 30자 이내 후기(선택)로 방문 기록을 생성할 수 있다.
- 사용자는 본인이 남긴 기록을 언제든 수정·삭제할 수 있다.
- 크루원은 다른 크루원이 남긴 기록에 좋아요 같은 반응을 남길 수 있다.
- 기록의 공개 범위는 CREW_ONLY를 기본값으로 하며, 사용자가 크루에 속한 경우 같은 크루원에게만 보인다.
- 본인 페이지에서는 지도 형태로 다녀온 암장과 평가를 시각적으로 볼 수 있다("클라이밍 맛집지도").
- 지도에서 지역이나 암장을 선택하면, 본인이 그곳에 남긴 후기를 볼 수 있다.

### NFR
1. **텍스트/별점 저장 Latency**: 암장·날짜·별점·후기 저장은 1초 이내에 완료돼야 한다. 사진·동영상 업로드는 별도로 비동기 처리해, 미디어 업로드가 끝나길 기다리지 않아도 기록 자체는 즉시 완료된 것으로 보여야 한다.
2. **접근 권한 반영 정확성**: 크루 탈퇴·강퇴 시, 해당 사용자가 남긴 과거 기록에 대한 다른 크루원의 접근 권한이 언제부터 어떻게 바뀌는지가 정의돼야 한다.
3. **미디어 저장 용량·내구성**: 사진·동영상 업로드 최대 용량과 저장 방식이 정의돼야 한다.

### Happy Path
사용자가 암장·날짜를 입력하고 저장하면 즉시 본인의 기록 목록과 지도에 반영되고, 사진·동영상은 백그라운드로 업로드된 뒤 자동으로 붙는다. 같은 크루원에게도 공유되고, 좋아요를 받을 수 있다.

### Unhappy Path
- 같은 날 같은 암장으로 중복 기록을 시도하면: 별개 기록으로 허용할지, 기존 기록에 병합할지, 확인을 물을지가 정의돼야 한다.
- 텍스트 저장은 성공했는데 미디어 업로드가 실패하면: 기록은 유지하고 미디어만 재시도할지, 전체를 실패로 되돌릴지가 정의돼야 한다.
- 동영상이 용량 제한을 초과하면: 업로드를 막고 어떤 안내를 보여줄지가 정의돼야 한다.
- 필수 필드(암장 이름)가 비어 있으면: 저장을 막고 어떤 안내 문구로 알릴지가 정의돼야 한다.
- 기록 작성 중 앱이 종료되거나 화면을 이동하면: 작성 중이던 내용(사진 포함)을 임시 저장(draft)해서 복구할지, 소실시킬지가 정의돼야 한다.
- 본인이 크루를 탈퇴한 뒤: 본인은 과거 기록을 계속 볼 수 있는지, 기존 크루원들은 더 이상 못 보게 되는지가 정의돼야 한다.
