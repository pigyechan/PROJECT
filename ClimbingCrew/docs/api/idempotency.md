# 멱등성 설계 — POST /records

대상 엔드포인트: POST /records (방문 기록 생성)

## 키 생성
클라이언트가 기록 저장을 시도할 때마다 UUID를 생성해 `Idempotency-Key` 헤더에 담아 보낸다. 사용자가 같은 저장 시도를 재시도(자동 재시도 또는 수동 재전송)하는 경우에는 새 키를 만들지 않고 처음 만든 키를 그대로 재사용해야 한다. 저장 버튼을 다시 눌러 완전히 새로운 시도를 시작하는 경우에만 새 키를 발급한다.

## 저장 위치
Redis에 `idempotency:{key}` 형태로 저장한다. 값은 처리 결과(HTTP 상태 코드 + 응답 body)이며 TTL은 1시간으로 둔다. 결제처럼 장기 보관이 필요한 도메인이 아니라 개인 기록이고, 사용자가 이후에도 직접 수정·삭제할 수 있어 중복이 생겨도 피해가 크지 않기 때문에 24시간보다 짧게 잡았다.

## 중복 요청 처리 흐름
서버는 요청을 받으면 먼저 Redis에서 해당 Idempotency-Key가 있는지 조회한다. 있으면 요청을 다시 처리하지 않고 저장해둔 응답을 그대로 반환한다(새 레코드를 만들지 않음). 없으면 정상적으로 기록을 생성하고, 그 결과를 같은 키로 Redis에 저장한 뒤 응답한다.
