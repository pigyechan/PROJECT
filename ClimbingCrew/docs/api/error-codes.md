# 에러 코드 체계 — 방문 기록(Records) API

## 4xx — 클라이언트 잘못 (비즈니스 에러)

| HTTP 상태 | 에러 코드 | 의미 | 클라이언트 대응 |
|---|---|---|---|
| 400 | VALIDATION_ERROR | 필수 필드(암장 이름, 날짜) 누락 또는 형식 오류 | 입력값을 확인해서 수정 후 재요청. 재시도해도 값이 그대로면 계속 실패함 |
| 400 | MEDIA_TOO_LARGE | 사진/동영상이 최대 용량을 초과함 | 파일을 압축하거나 더 작은 파일로 다시 시도 |
| 403 | CREW_ACCESS_DENIED | 크루원이 아닌 사용자가 CREW_ONLY 기록에 접근 시도 | 접근 불가 안내만 표시. 재시도해도 소용없음(권한 문제) |
| 404 | RECORD_NOT_FOUND | 존재하지 않거나 이미 삭제된 기록을 조회/수정/삭제 시도 | 목록을 새로고침해서 최신 상태 확인 |
| 409 | DUPLICATE_RECORD | 같은 날 같은 암장으로 이미 기록이 있음 | 사용자에게 기존 기록에 병합할지, 별개로 남길지 확인창 표시 |

## 4xx — 클라이언트 잘못 (인증/트래픽)

| HTTP 상태 | 에러 코드 | 의미 | 클라이언트 대응 |
|---|---|---|---|
| 401 | AUTH_REQUIRED | 로그인하지 않았거나 토큰이 만료됨 | 재로그인 화면으로 이동 |
| 429 | RATE_LIMITED | 짧은 시간에 너무 많은 요청을 보냄 | 안내된 시간만큼 대기 후 재시도 |

## 5xx — 서버 잘못 (시스템 에러)

| HTTP 상태 | 에러 코드 | 의미 | 클라이언트 대응 |
|---|---|---|---|
| 500 | INTERNAL_ERROR | 서버에서 예상하지 못한 오류 발생 | Idempotency-Key로 안전하게 재시도. 반복되면 문의 유도 |
| 503 | MEDIA_STORAGE_UNAVAILABLE | 미디어 저장소 장애로 사진/동영상 업로드 불가 | 텍스트 기록은 이미 저장됐다고 안내하고, 미디어만 나중에 재시도 |
| 504 | DB_TIMEOUT | DB 응답 지연으로 요청 처리 실패 | Idempotency-Key로 안전하게 재시도 |

## 분류 기준
- **비즈니스 에러**(400/403/404/409): 요청 자체는 서버에 잘 도달했지만, 도메인 규칙이나 입력값 문제로 처리할 수 없는 경우. 클라이언트가 요청 내용을 바꿔야 해결됨.
- **시스템 에러**(500/503/504): 서버·인프라 쪽 문제로 처리에 실패한 경우. 클라이언트는 요청을 바꿀 필요 없이 그대로 재시도하면 되고, 이때 Idempotency-Key가 중복 생성을 막아준다.
